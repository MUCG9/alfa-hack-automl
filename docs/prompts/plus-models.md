# Промпт для Plus A — модели и исполнение

Ты владелец ML-исполнения нашего Alfa Hack CPU AutoML-агента в клоне https://github.com/MUCG9/alfa-hack-automl. Прочитай README, program.md, docs/webinar_20261021.md, docs/v3_contract.md, docs/parallel_work.md, docs/v2_validation.md и свой код. Зафиксируй общий base SHA и создай ветку feat/v3-model-adapters. V2 уже отправлена, score карточки 1694.145; не перезаписывай release/solution-v2.zip и не обещай private-баллы.

Твоя зона: agent_worker.py, model_utils.py, ensemble_cache.py, при необходимости task_models.py, новые tests/test_model_adapters.py и docs/research/models.md. Pro владеет parser/spec/metrics/split/CSV, Plus B — runner/policy/packaging. Не правь их файлы и общий контракт без согласования. Начинай по записанному контракту 0.1 с синтетических specs, не жди завершения Pro.

Реализуй CPU make_task_model и worker-адаптеры для multioutput regression, multilabel classification и ranking на уже разрешённых библиотеках. Для ranking нужны корректные query groups/sizes, отделённая по query валидация и score, не обычная регрессия под видом ranker. Сохрани single-target пути v2, классы/вероятности и порядок output targets. Проверь положительный класс, unseen categories, редкие классы, NaN/inf, матрицы нескольких целей и refit на полном train. Внешний validation не использовать для stopping или калибровки: только inner fitting split. Секретов API в worker быть не должно. Новые результаты должны быть обратно совместимы с прежними JSON job/result и numpy cache, без pickle.

Первые результаты — маленькие unit-тесты по контракту и поддерживаемые методы estimator, затем реальное end-to-end обучение каждого нового типа на synthetic. Изолированно измерь полезные улучшения single-target (калибровка/веса/ансамбли) только после совместимости; не смешивай пять изменений и не оптимизируй исключительно public. Доказательства: tests фактически запущены, честные метрики на заданном split, время/RAM и отрицательные результаты. Public-данные получить из пакета организаторов, не из Git. Локальное качество не переводить в выдуманный официальный score.

Лимиты сервера на задачу: 8 CPU, 32 GB RAM, 30 GB диск, 3 часа. Requirements не менять, weights/данные в Git не добавлять. Прогон без Qwen так и пометить. Не пушить main, не делать submit/cloud-покупки. Итог: отдельная ветка/SHA, список поддерживаемых spec форм, команды тестов и результаты, ограничения, что требуется от Pro/Plus B. Публиковать можно только собственную ветку; merge и release утверждает капитан.
