# Материалы капитану на встречу 22 октября

## Что открыть сначала

1. `team_briefing_final.pptx` — 16 редактируемых слайдов с заметками для выступления.
2. `run_results.md` — что действительно запущено, какие метрики получены и что остаётся неизвестным.
3. `organizer_clarifications.md` — уточнения из экспорта с прямыми ссылками на сообщения организаторов.
4. `team_workflow.md` — пять владельцев, задачи двух Pro-участников, проверка изменений и ближайшие 24 часа.
5. `prompt_pack.md` — общий контекст и готовые задания для пяти участников.
6. `backlog.md` — приоритетные задачи для переноса в GitHub Issues/Project.
7. `captain_notes.md` — простое объяснение кейса, сценарий встречи и вопросы команде.
8. `week_plan.md` — недельные контрольные точки и индивидуальные задания на три дня.
9. `risk_register.md` и `daily_templates.md` — актуальные риски и готовые формы отчётов/решений.
10. `github_project.md` и `github_issues.csv` — структура доски и задачи для переноса после выбора репозитория.
11. `data_audit.md` — аудит исходных материалов и риски данных. `public_data_audit.ipynb` содержит повторную проверку CSV: три code cells выполнены последовательно в свежем Python-процессе, фактический stdout сохранён. Запуск через Jupyter kernel отдельно не проверялся.

Код находится в `../`. В конкурсный архив `../release/solution-v1.zip` включены только корневые `.py` и исходный `requirements.txt`.

Рабочий проект находится уровнем выше этой папки docs. Этот проект включён в полный передаваемый комплект team_handoff.zip. Внутри лежат код, smoke tests, упаковщик, документы и неизменённый отправленный ZIP. Приватный ключ и исходные train/test в него не включены.

## Текущее состояние

- Обе публичные задачи пройдены end-to-end локально с реальными вызовами Qwen.
- Созданы и проверены файлы предсказаний для всех test-строк.
- Измеренные локальные показатели: regression RMSE **43.60655**, classification Macro F1 **0.60358**.
- По общему ключу за окно работы потрачено около **10.80 ₽ из 600**.
- После отдельного согласия капитана отправлена **одна** попытка на платформу.
- Кабинет подтвердил приём ZIP и показал 2 оставшиеся попытки. Последний наблюдённый статус хранится в `platform_status.json`; score не подменяется локальной метрикой.

Сводные данные — `results_summary.json`, детали — `evidence/`. Предсказания сохранены как `regression_submission.csv` и `classification_submission.csv`. Эти CSV не надо загружать вместо агента в трек AutoML.
