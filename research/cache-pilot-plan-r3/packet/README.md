# Selector cache: prospective six-callback pilot

This packet is a plan. It does not authorize implementation or launch, and assigns no deadline. The active R4 campaign, its 430 immutable files, the existing cache prototype, canonical source, STATE and Git were not changed. Preparation read saved JSON, static source and split-position NPZ arrays; it loaded no raw examples or labels, imported no runtime, and ran no tests, fits, API or network calls.

The single factor is the existing leaf-local `selector_importance_cache` boolean. A future isolated copy must use one reviewed runtime and identical fitting-input diagnostics in both arms. Cache and diagnostics remain default OFF outside this pilot. The diagnostic collector and its timing have not been implemented or qualified by this packet.

`anchors.json` pins the original job, recipe, semantic spec and split hashes. `data-fingerprints.json` records the exact ordered train/validation positions, dtype and hashes, plus the five pristine input hashes per task. The classification anchors share the frozen 56,711 / 13,818 split; regression uses 22,054 / 12,946. Future jobs preserve the recipes, hypothesis, feature code, two threads, `full_fit=false`, absent `fit_iterations`, and effective default seed 42. Only declared path relocation, the cache flag and a common diagnostic option may differ. No source job or input copy was materialized here.

The two class callbacks were chosen from cost/scope evidence: both have a possible matching-inner repeat in each existing feature view. The regression callback is a no-hit control with distinct inner/outer scopes. The old 171.985 seconds of repeated selector calls is not measured cache savings. Parent-row or selected-column equality does not establish equality of the actual teacher inputs.

`diagnostic-contract.json` requires the actual ordered CatBoost-prepared fitting X, index, schema, category metadata, transformed fitting y, weights, row positions, teacher settings, selection scope and libraries. The common probe runs independently on every request in both arms, including hits. ON additionally pays the existing cache hash/lookup/store cost; the probe must not provide a free key. OFF must receive the same explicit scope for diagnostics without enabling a cache. `history_min_periods` is the runtime field; the historical subset's `history_minimum_periods` is not a usable exact key.

Keep the prototype's `teacher_fit_seconds` truthfully labeled as constructor + fit + importance extraction. A future common collector must separately time the actual `.fit` call, constructor, importance extraction, digest/I/O, cache operations, selector and complete worker/parent. Reused importance time is not saved wall time. A fresh leaf cache stores only importance and column metadata, at most 4 entries / 262,144 conservatively counted bytes; no cross-view, worker, callback, task or fitting-namespace reuse is permitted.

The prospective 7,200-second upper bound consists of 300 seconds for no-fit contracts, two 900-second full source gates, two 480-second exact-unpacked gates, 2,640 seconds for the six workers, 180 seconds for their cleanup/seals, 600 seconds for independent artifact audit, and 720 seconds for setup/guards/receipts. This is a maximum, not an ETA. Full remaining parent caps and the final audit reserve must fit before admission; immediately recheck before Popen. Root alone may later assign one absolute and monotonic clock after review/publication and actual predecessor cleanup. No retry, cap clipping, clock borrowing or reinvestment is allowed.

The future harness must register the existing 12 cache methods, preserving every prior assertion. The baseline expectation is 451 checks / 46 scripts, and the candidate expectation is 463 / 47 if that is the sole registry addition. Baseline checks repeat in candidate/unpacked runs; these are not 914 unique checks. Every source gate needs the same nine historical metadata files and ten pristine public inputs in `technical-fixtures.json`. A missing fixture is a technical failure. The original failed f3 attempt remains evidence, and is not a passed gate for this pilot.

Use a short future output root `work/k1` only after an actual producer-derived Windows path audit. The flat executable entry point is `automl_worker.py`; flat `agent_worker.py` is an import alias and has no executable main. One logical job runs at a time, with two model threads, 1.5 GiB per worker subtree and 2 GiB for the owned tree. Use the canonical ResearchLock and reviewed strict PID/create-time, orphan and cleanup handling. A bootstrap parent/child pair is one logical job. Any ownership denial fails closed. Source, inputs, job, predictions and CSV must be sealed before paired verification.

`parity-and-failure.json` freezes numerical tolerances and exact schema/selected-column/iteration/CSV requirements. It permits the actual test NPZ schema without an invented `row_position`; test ID/sample order and CSV/argmax must instead be verified. All six slots remain explicit. Failures/timeouts leave missing quality and savings null. Incomplete pairs cannot establish a speedup. Late technical failure clears nested and aggregate qualification claims. The callback CSV is not a full-agent final refit.

A mechanism pass and descriptive local timing gain would still leave default OFF, no promotion and no submission. Both-task full-agent confirmation, refit/CSV and release qualification against the strongest V11/V16 procedure require a separate reviewed protocol. The deferred selector-free HPO protocol is unchanged; this cache cannot save teacher work where there is no teacher.

Before implementation or launch, root needs the actual common diagnostic source and independent review, registration and exact archive/module/library hashes, complete dependency/path inventories, fresh zero-skip source/unpacked gates, a sealed-pair verifier, and actual predecessor ownership/lock proofs. The future archive, source and clocks are intentionally null in `protocol.json`.
