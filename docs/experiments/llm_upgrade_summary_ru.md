# Что удалось извлечь из советов LLM

22октября2026, ветка work/llm-upgrade-20261022. Главный полезный принцип — не
переписать всё по одному промпту, а отдельно проверять каждую гипотезу против
сильного контроля. Подробные исходные советы и первичные ссылки: v11_llm_review.md.

## Реальное улучшение

Доведён до рабочего агента положительный эксперимент коллеги: ансамбль двух
представлений категориальных данных. Первая модель видит исходные признаки,
вторая — дополнительно сглаженные статистики категорий и их пар. Для fitting
строк статистики строятся без собственной feature-hash группы, inner/outer/full
преобразования разделены. Внутри рецепта фиксированные50/50, никакого подбора
весов по внешним меткам. Деревья числа итераций сохраняются при общем ансамбле.

Полный default pipeline V11: MacroF1 .653281240→.659317843, оба контрольных среза
лучше, полный refit/export/integrity проходит. Регрессия RMSE35.447231558 и CSV
совпадают с history4. Это reused-public оценка: .75 и75–85официальных баллов
не достигнуты и не обещаются. Чем больше проверок на public, тем осторожнее вывод
о переносе на неизвестные задачи.

## Почему часть красивых идей не включена

- Threshold tuning уже был в сильном контроле. Дополнительный ограниченный
  Nelder–Mead улучшил inner objective, но ухудшил оба outer F1. Без положительного
  outer результата нельзя объявлять его прорывом или увеличивать поиск posthoc.
- Обязательный balanced может повторно умножить существующие class weights.
  Оставлены проверенные мягкие веса и текущая калибровка, не два штрафа сразу.
- AutoGluon1.3.1 действительно обучен, а не только импортирован. Проверенная
  GBM+CAT процедура медленнее и хуже контроля. Её preprocessing дополнительно
  изолирован: по умолчанию framework объединяет train+tuning для featuregen.
- Log1p меняет функцию потерь; обратный expm1 не гарантирует минимум RMSE.
  Две inner-only поправки обратного преобразования проверены на3forwardcuts;
  обе ухудшили последний поддержанный срез. Оставлены выключенными.
- Leaf10 вместо25 в обоих views ухудшил оба F1. Меньший лист сам по себе не
  решает конфликты дубликатов и редких классов. Без положительного screen CV нет.
- Жёсткие имена сетевых/строительных колонок и возраст относительно2024 не
  универсальны. Действующие признаки опираются на схему и fitting данные.
- df.eval не sandbox. Сохранены ограниченные row-wise AST transforms в worker
  без credentials; это всё ещё не полноценная security sandbox.
- Импорт LightAutoML не доказывает корректность splits/metric/refit/resources.
  Локально библиотеки нет; новые зависимости и runtimepip не добавлялись.

## Что сохранено без регрессии

Fail-safe CSV до дорогих операций, атомарные working checkpoints, проверка ID/
порядка/формы/NaN, общий deadline/API ledger, typed recipes и соседние api.py
границы. Никакого монолитного переписывания и нарушения original requirements.
258unique source checks и23повторных exact-unpacked проходят для latestV16;
полный default parity этого snapshot проверяется отдельно, статус в current.md.

Живой Qwen в этом этапе не вызывался: private env отсутствует. Mock/localHTTP
не выданы за live proof, исторический открытый ключ не переносился в команды.
Нового official submit нет, вопрос о разрешении одной попыткиV11 ждёт ответа.

Следующий разумный этап после передачи — разбор selection trace и отдельная
новая измеримая гипотеза, а не повтор отрицательных trials или обещание private.
