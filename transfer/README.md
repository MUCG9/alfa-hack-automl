# Перенос V11/V16 на другой ноутбук без повторного обучения

Капитан явно разрешил перенос исследовательских кэшей через GitHub.
Комплект v11-v16-caches/ содержит848 файлов,483 уникальных объекта,
5 ZIP-частей общим размером170413863bytes (около163MiB).
Каждая часть меньше GitHub-лимита100MiB. Повторяющиеся данные хранятся один раз.

Включены предсказания/вероятности public задач, позиции split, результаты,
метаданные, журналы метрик TSV, task.md и замороженные копии исходников прогонов.
НЕ включены исходные train/test/data_dictionary/sample_submission CSV,
ключи/.env, окружения, модели/их обученные веса, logs, pycache.
Это research bundle, НЕ конкурсный submission ZIP.

## Получение

Актуальная ветка: work/llm-upgrade-20261022. Если на втором ноутбуке уже идёт
разработка в другой ветке, сначала сохрани её изменения своим коммитом.
НЕ сбрасывай её, НЕ заменяй весь проект и НЕ переключайся на старыйmain.
Можно забрать только новые tools/transfer_caches.py и transfer/ из этой ветки
после git fetch origin, не заменяя остальной код коллеги. Перед переносом
проверь, что эти пути не содержат собственных несохранённых изменений.

## Проверка и восстановление — из корня репозитория

```bash
python tools/transfer_caches.py verify
python tools/transfer_caches.py restore
```

Только стандартная библиотека Python, безpip и ML-обучений.
Сначала проверяются SHA256 частей и ВСЕХ объектов, затем все пути и конфликты.
Другой существующий файл НЕ перезаписывается; identical файл пропускается.
Восстановятся точные относительные пути:

- test-runs/llm-upgrade-20261022/featureviews1-full/
- test-runs/llm-upgrade-20261022/final-default-parity/

V11:task-00classification/task-01regression. V16:task-00regression/task-01classification.
Восстановленные test-runs остаются ignored: не добавлять их повторно вGit.

Важно: неизменяемые JSON сохраняют старые абсолютные пути и fingerprint.
Restore печатает root_mapping со старого корня проекта на новый.
Loader/BASE-01 должен применять mapping при чтении, НЕ переписывать evidence.
Исходные organizer CSV нужны отдельно для пересчёта групп и метрик; если они
уже есть на втором ноутбуке, проверить их SHA по docs/handoff/public_inputs.json.
Пути на исходный work/evaluation за пределами repo сопоставлять отдельно с
локальной копией разрешённых данных. В архиве этих CSV специально нет.

Артефакты независимых старых/отрицательных исследований в этот bundle не входят;
их переносимые protocols/results уже есть в docs/experiments. Не подменять
точные V11/V16 прогнозы файлами V10. Повторное обучение для BASE-01 не нужно.
