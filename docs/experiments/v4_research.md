## Что обнаружено

Главная проблема регрессии — выбор моделей на случайном разбиении при переходе
теста в следующий период. В public train наблюдаются периоды 1–5, весь test
относится к периоду 6. Прежний ансамбль хорошо выглядел на случайном holdout,
но на последнем временном backtest его RMSE оказался 79.4754. Автоматические
признаки повторяющихся объектов и корректный временной отбор дают существенно
лучший результат на двух общих forward-срезах. Это public-исследование, не оценка
официальных баллов и не независимый закрытый тест.

## Данные и протокол

Оба task.md и восемь CSV получены из официальной Drive-папки, указанной в кейсе.
Все десять SHA совпали с `docs/handoff/public_inputs.json`. Предобученные модели
исключены условиями кейса. Qwen предлагает признаки и рецепты; ML обучается на
предоставленном train. Ключ хранится только в приватном окружении процесса.

Тяжёлые jobs выполняются последовательно, два потока, worker watchdog 1200 s
и локальный лимит 1.7 GiB. Лимит отражает доступную память этого ПК, а не лимит
платформы 32 GiB. Для сквозных прогонов отдельный watchdog 10100 s и штатный
бюджет решения 9900 s. Среда измерений: Python 3.12.3, numpy 1.26.4, scipy 1.12.0,
pandas 2.2.3, sklearn 1.5.2, LightGBM 4.6.0, XGBoost CPU 2.1.4, CatBoost 1.2.8.
Используется `test-runs/venv-core`; другие окружения в сравнениях не смешиваются.
Исходный `requirements.txt` сохранён без изменений.

Рецепты и compiled source заморожены перед запуском. Benchmark сохраняет hashes
входов, модулей и split, статус, время, peak RSS и predictions. Legacy seeds42/43
сохранены отдельно. Для времени: обучение на периодах <5, проверка на 5;
второй backtest обучается на <4, проверяется на 4 и исключает будущий период5.
Inner stopping тоже использует только историю относительно своего validation.
Для classification финалисты проверяются полной CV с разделением точных
дубликатов между folds; fold mean/std и pooled OOF считаются отдельно.
Повторно используемые public folds после настройки не являются unbiased estimate.

## P0: корректность и воспроизводимость

Исправлены дерево процессов watchdog (включая detached sessions), cleanup при
ошибках и прерываниях, проверка exit code перед принятием worker result.
Preprocessing переобучается внутри каждого inner/outer/full fit. Ошибка fit больше
не скрывается под rare-class fallback. Распакованный release выбирает собственный

## Добавленные возможности и границы

Runtime: консервативное обнаружение документированного будущего периода,
auto-validation с явным legacy-режимом и диагностикой fallback; time confirmation;
train-only target encoding, composite groups/auto-history, counts/recency opt-in;
one-vs-all, training OOF factors, до трёх редких парных специалистов opt-in.
Расширения проходят общий normalize/capabilities и попадают в контекст Qwen.
Выбор остаётся по фактической целевой метрике; методы не включаются все сразу.

Dev evaluation: `tools/benchmark_candidates.py` поддерживает paired screening,
полную CV с exactly-once OOF и forward backtests; `tools/select_finalists.py`
проверяет совпадение входов и split hashes. Полная CV здесь — инструмент
исследований; production search использует search/confirmation, не все K folds.
StratifiedGroupKFold может оставить класс без support на отдельном validation fold
даже при достаточном числе групп: такие классы записываются в
`validation_missing_classes`; отсутствие класса в fitting fold запрещено.
Все модели сравниваются на одних folds, Macro F1 использует общий class order,
а pooled OOF оценивается отдельно.

Текст: TF-IDF + logistic и TF-IDF + bounded TruncatedSVD (LSA), обучаемый с нуля,
проверены на synthetic tiny vocabulary и class-order/probability output.
Public text-метрик нет; pretrained embeddings не используются. Эти методы
не продвигаются в default только по synthetic-тесту.

Не реализованы SMOTENC, balanced-subset ensemble, stacking и pseudo-labeling.
Их стоит проверять отдельными абляциями после текущих измерений, а не объявлять
готовыми по наличию в backlog. Предобученные эмбеддинги запрещены кейсом.
