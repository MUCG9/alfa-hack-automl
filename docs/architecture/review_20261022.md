## Изменения структуры относительно v2

Canonical implementation находится в `src/automl`: task_understanding,
evaluation, search, execution, publishing, infrastructure, contracts.
Корневые agent-файлы — compatibility shims. Пять model adapters отделены от
worker; registry описывает capabilities. DataPolicy отделяет weighting,
sampling и masking; lineage хранит исходные fitting rows. Сборщик компилирует
пакет в плоский архив. Это модульный монолит с subprocess, не сетевые сервисы.

В search сохранены portfolio → Qwen/fallback → seed43 confirmation → cached
blend → full refit. XGBoost уже реализован, CV по всем folds и stacking — нет.
Текст по-прежнему TF-IDF + SGD/Ridge, теперь есть кандидат с char n-grams.

## Выводы по коду

- Сильная основа: отдельные model adapters, неизменяемые historical releases,
  проверка split/parent lineage, train-only data policies и checkpoints.
- `execution/worker.py`: preprocessing по outer fitting rows предшествует inner
  split. Часть решений видит inner validation X; изоляцию надо довести до каждого fit.
- Там же широкий `except ValueError` может обозначить ошибку fit как rare-class
  fallback. Нужны диагностика и отдельная обработка ожидаемой нехватки классов.
- `evaluation/service.py`: только первый fold; два seed holdout не заменяют полную CV.
- `scripts/benchmark_release.py`: watchdog завершает process group координатора;
  worker запускается в отдельной session и может пережить его. Этот gap уже
  упомянут в передаче и подтверждён чтением кода, runtime-эксперимент здесь не проведён.
- Новые методы выбирать после полного baseline: CV/OOF для финалистов, мягкие
  веса/decision factors, diversity ensemble, затем OVR/stacking, copy-only control,
  balanced subsets и LSA. Не считать эти методы уже добавленными.
