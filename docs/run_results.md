# Фактические результаты первой версии

Дата: 21 октября 2026 года. Код не обучал модели заранее для упаковки: агент сам разобрал обе задачи и обучил модели во время запуска.

## Итог локальной проверки

| Показатель | Регрессия | Классификация |
|---|---:|---:|
| Основная метрика | RMSE | Macro F1 |
| Константный прогноз на том же split | 59.71457 | 0.04902 |
| Лучший измеренный вариант | **43.60655** | **0.60358** |
| Весь прогон, 3 эксперимента + final fit | 73.629 сек | 575.963 сек |
| Максимальный RSS среди experiment workers | 325.7 МБ | 1 062.8 МБ |

Время включает API в конкретных локальных прогонах. Это не обещание такого же времени на платформе. RSS указан для отдельных workers, не для суммы всех процессов и не для полного Docker-контейнера.

## Регрессия

Random holdout 20%, seed 42. Train для fit: 42 646 строк, validation: 10 662. Метрика на исходной шкале target.

| Эксперимент | RMSE | Решение |
|---|---:|---|
| LightGBM, исходные признаки | 43.69731 | baseline v1 |
| Qwen: log1p(target) | 46.21860 | отклонён как ухудшение |
| Qwen: derived features и missing indicators | 43.60655 | выбран |

Qwen сгенерировал функцию `transform(df)`: масштабы площади, индикаторы пропусков, отношение/сумма градусо-суток, размах температур и другие простые признаки. Код выполнился в worker без target/id.

Разница 43.69731 → 43.60655 небольшая, один split не доказывает статистическую устойчивость. Этот вариант нужно перепроверить по fold/seed и по периодам. Гипотеза Qwen о log-target ухудшила RMSE: агент её отверг, а не сохранил по доверенному текстовому объяснению.

## Классификация

StratifiedGroupKFold, 5 folds, используется только fold 0. Группа — hash всех входных признаков без id/target. Train: 70 529 строк, validation: 17 141. Общих feature-hash между частями: 0. Это один grouped holdout, а не результат полной 5-fold CV.

| Эксперимент | Macro F1 | Accuracy | Решение |
|---|---:|---:|---|
| LightGBM, без весов | 0.57836 | 0.82796 | baseline v1 |
| Qwen: balanced class weights | 0.60358 | 0.77959 | выбран |
| CatBoost, резервная гипотеза | 0.53072 | см. evidence | отклонён |

Macro F1 вырос, а Accuracy упала. Для кейса это осмысленный компромисс: основная метрика одинаково учитывает редкие классы. У `Worms` F1 поднялся с 0.25 до 0.51613. Но в validation всего 19 примеров этого класса, поэтому необходима проверка устойчивости.

Нельзя напрямую сравнивать эти значения с random split другой команды или leaderboard: там другой набор объектов и иная нормировка.

## Что произошло с Qwen

- Выданный ключ проверен реальным небольшим запросом.
- Использован `qwen/qwen3.8-27b` через endpoint из инструкции организаторов.
- На ранних запросах max_tokens 2200/4096 иногда полностью расходовался на reasoning; готового JSON не было.
- При max_tokens 8192 получены проверенные планы и код признаков. Один classification-ответ всё равно обрезался, поэтому отработал детерминированный fallback.
- Были timeout и JSON errors. Они не уничтожили ранний или лучший submission.
- Счётчик командного ключа после серии тестов: 10.80213 из 600. Остаток: примерно 589.20. Поскольку ключ общий, это изменение счётчика за окно работы, а не независимый биллинг исключительно этого процесса.
- По инструкции сброс — 03:00 MSK. Проверка на платформе не входит в эти 600 ₽, что подтверждено организатором.

## Какие проверки реально выполнены

- Синтаксис корневых модулей и плоская структура ZIP.
- Отсутствие ключа в ZIP.
- Побайтовое совпадение requirements с файлом текущей платформы.
- Запуск после распаковки ZIP с корневыми модулями.
- Четыре искусственные задачи: новые имена полей, числовые labels, unseen categories, длинная текстовая колонка.
- Запрет импорта в generated feature code.
- Оба публичных end-to-end прогона с реальными Qwen-запросами.
- Полное переобучение выбранных recipes и создание submission для 22 449 / 41 166 строк.
- Проверка колонок, ID, порядка строк, NaN/inf и допустимых labels.

## Официальный score

Разрешённая пользователем одна попытка отправлена. Кабинет показал `solution-v1.zip`, «Решение находится на проверке» и 2 оставшиеся попытки. До появления результата official score не установлен.

Актуальное состояние записано в `platform_status.json`. Локальные метрики выше не переводятся в баллы платформы: скрытые baseline-значения и hidden targets недоступны.

## Доказательства и ограничения

`results_summary.json` содержит сводку. В `evidence/` сохранены reports, split, experiment results, финальные планы Qwen и usage. Полные CSV не отправлялись Qwen: только текст условия, словарь, профиль и метрики.

Две невиданные private-задачи не проверены. Код первой версии не является доказанно универсальным решателем любых ML-задач. План команды должен закрыть эти ограничения прежде, чем оптимизировать небольшие десятые доли public score.
