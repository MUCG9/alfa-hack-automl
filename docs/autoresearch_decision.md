# Что берём из autoresearch

Изучены 21.10.2026: [README](https://github.com/karpathy/autoresearch), [program.md](https://github.com/karpathy/autoresearch/blob/master/program.md), [prepare.py](https://github.com/karpathy/autoresearch/blob/master/prepare.py), [зависимости](https://github.com/karpathy/autoresearch/blob/master/pyproject.toml).

Исходный проект автоматизирует эксперименты по обучению небольшой языковой модели на одной NVIDIA GPU. У него фиксированные оценщик и бюджет обучения, изменяемый training-код, журнал и принятие/отклонение вариантов. Его метрика bits-per-byte не относится к нашему кейсу. Его зависимости и CUDA-обучение не переносим в конкурсную сборку.

Решение для команды: развивать наш CPU AutoML по тому же принципу контролируемого исследования. Зафиксированный оценщик, сравнимые данные/разбиения, ограниченные эксперименты, сохранение неудач и повторная проверка полезны без GPU. Это инженерная адаптация идей; чужой репозиторий не скопирован, не форкнут и не развёрнут.

В v2 уже реализованы:

- ограниченный поиск рецептов с Qwen, наследование удачного кода и параметров;
- защита от повторных конфигураций и старых result-файлов;
- отдельный inner holdout для stopping/порогов;
- проверка до трёх лучших вариантов на втором разбиении при наличии времени и условное смешивание;
- сохранение рабочего ответа до долгого финального обучения;
- журнал `results.tsv`, параметры, метрики, время и потребление памяти;
- SHA исходников, задачи и входных данных до/после запуска.

Отличия от оригинального подхода намеренные: нет бесконечного цикла, автоматических откатов Git и GPU; Qwen не может переписывать оценщик. Лимиты хакатона важнее максимального числа экспериментов. Полноценной security sandbox Python-процесс с AST-фильтром не является. Повторный подбор на public всё равно может переобучить команду под public — второй split снижает риск, но не устраняет его.

Общий протокол — `program.md`. Полные результаты v2 — `v2_validation.md` и `v2_results.json`; версия уже отправлена. Видео обработано целиком: `webinar_20261021.md`. Актуальный следующий этап — три параллельных владельца, один Pro и два Plus, в `parallel_work.md`. Новые требования формируют задачи v3, не реализованные возможности v2.
