# FE-02: сохранить исходные признаки при CatBoost selection

Протокол до новых fits/результатов. Обычный top32 в exploratory MVP удаляет
часть исходных входов: two-view MacroF1 .6502622584145485 против сохранённого
single control .6558634659956402 на том же search split. F1 Worms .68421→.5625,
также нарушен supported-class gate для Analysis. Это мотивирует гипотезу,
но не доказывает причину изменения. Полный FE-01 paired screen ещё впереди.

Одна новая политика: union всех исходных `spec.features` с обычным CatBoost
top32. Teacher, веса,100iterations/depth5 и отдельный fit каждого scope остаются
прежними. Порядок колонок сохраняется. Когда представление содержит только
исходные входы, teacher не нужен: union при любом ranking сохраняет все колонки.
В engineered view teacher выбирает top32 среди всех колонок, затем возвращаются
исходные плюс выбранные; это НЕ32 лучших engineered features отдельно.

Контроль — qualified SINGLE categorical two-view LightGBM, selector OFF.
Другие параметры, preprocessing, calibration и данные не меняются. Treatment —
тот же рецепт с developer dispatcher `tools/protected_selection_worker.py` и
selector32. Это не production integration и не полномочие менять canonical source.
Dispatcher копируется/хешируется вместе с frozen sources; control вызывается
неизменённым canonical worker. Каждая модель учит selection в собственных
fitting rows; никакого общего outer/inner cache.

Запускать только ПОСЛЕ текущего MVP и overnight queue, когда проверены identities,
descendants и свободен training lock. Classification group cuts42/43,2threads,
1536MiB/600s per worker, общий cap3600s. Две пары control/treatment; новые immutable
split arrays/source/input fingerprints сохраняются. Не реконструировать старые
partitions из predictions и не подбирать union/top_k по результатам этого screen.

`tools/followup_fe02.py` может ожидать owned overnight identity/descendants,
не захватывая training lock во время ожидания. После завершения predecessor
проверяет допустимый статус, тот же frozen source и dispatcher/benchmark hashes,
затем получает exclusive lock. Общий wait+screen cap21600s, fit cap3600s;
новый screen не начинается без2460s на четыре максимальных worker windows и
завершение. Busy lock не снимается и не приводит к fit. Отдельная no-fit
проверка этой блокировки PASS. Итог независимо пересчитывается в verified.json.

Gate: MacroF1 лучше на КАЖДОМ cut, loss<=.01 для классов с >=100 независимых
fitting feature groups, положительный gain без rarest class. Пересчитать metrics
из фактических CSV и saved split arrays. Отдельно сообщить время selector,
число teacher fits/skips, feature counts, peak memory и wall time. Уменьшение
числа колонок само по себе не означает ускорение или ML gain.

Отрицательный результат сохраняет qualified control и не приводит к promotion.
Положительный screen требует3fold GROUPED CV всей фиксированной процедуры
(каждый selector/calibration заново внутри fold), exactly-once coverage,
fold mean и pooled score. Затем optional integration, полный агент на двух
задачах/refit/CSV/integrity, source и exact-unpacked gates. Все эти development
результаты reused-public, не private/official score.
