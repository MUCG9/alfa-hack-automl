# Как работать вместе

Актуальные три владельца — `docs/parallel_work.md`, общий API — `docs/v3_contract.md`, готовые задания — `docs/prompts/`. Единый протокол — `program.md`. Прежние P1–P5 и `team_workflow.md` — исторический план, не текущее назначение.

1. Выберите одну задачу из `docs/backlog.md` и согласуйте владельца.
2. Создайте отдельную ветку и меняйте один проверяемый фактор.
3. Передайте ИИ общий контекст, свой issue и актуальный контракт модуля. Не вставляйте API-ключ в prompt.
4. Сохраните фактический запуск, split hash, метрику, время и ограничения проверки.
5. Откройте pull request, получите независимый review. Капитан отдельно утверждает release и расход submit-слота.

Ключи задавайте через окружение. Исходные train/test, локальную среду и большие generated artifacts не коммитьте. Не меняйте исходный `requirements.txt`, evaluator или split ради красивого результата. Следующий ZIP собирайте упаковщиком и проверяйте после распаковки.

Предсказания публичных прогонов исключены из Git. `release/solution-v1.zip` и `release/solution-v2.zip` — неизменяемые отправленные архивы. При передаче корневой код побайтно соответствует v2; следующую версию развивать в трёх отдельных ветках. Локальная метрика не является официальным баллом.
