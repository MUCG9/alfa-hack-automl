# Работа трёх участников: один Pro, два Plus

Текущая исходная точка — отправленная v2 с показанным баллом **1694.145** против **857.742** у v1. Результаты не гарантируют private. Репозиторий: https://github.com/MUCG9/alfa-hack-automl (приватный). Перед клонированием капитан добавляет нужные GitHub-аккаунты; приглашения автоматически не отправлялись.

## Распределение

1. **Pro — TaskSpec и универсальность, самая объёмная задача.** Ветка `feat/v3-task-contract`. Владелец `agent_core.py`, новых `task_spec.py`/`task_adapters.py`, `tests/test_task_contract.py`, `scripts/audit_task_contract.py`. Понимание задачи до поиска, схема/метрика/выход, context-aware validation, закрытие loader/metric пробелов вебинара.
2. **Plus A — модели и исполнение.** Ветка `feat/v3-model-adapters`. Владелец `agent_worker.py`, `model_utils.py`, `ensemble_cache.py`, при необходимости нового `task_models.py`, новых `tests/test_model_adapters.py`. CPU multi-target/ranking, классы/вероятности, inner stopping/refit и ансамбли. Существующие общие тесты не переписывает ради прохождения.
3. **Plus B — поиск, надёжность и интеграция.** Ветка `feat/v3-search-runner`. Владелец `agent_runner.py`, `agent_policy.py`, `solution.py`, упаковщик/benchmark, новых `tests/test_runner_v3.py`. Ранний TaskSpec, эффективные параметры и dedup, API/deadline, общая проверка сборки. Упаковщик не включает secrets/config/data/weights.

Готовые промпты находятся в `docs/prompts/pro.md`, `plus-models.md`, `plus-runner.md`. Они рассчитаны на агента в собственной рабочей копии, не на одновременную запись в одну папку. Подписка определяет распределение объёма работы, а не автоматически доступное GPU/железо.

## Начало работы и контроль конфликтов

Каждый клонирует репозиторий и создаёт свою ветку от одного и того же commit `main`, зафиксированного капитаном. Все сообщают `git rev-parse HEAD`; при разных исходных SHA сначала синхронизируют базу. Файлы `release/solution-v2.zip` и `docs/v2_results.json` фиксируют фактическую отправленную версию, даже если main потом изменится.

```bash
git clone https://github.com/MUCG9/alfa-hack-automl.git
cd alfa-hack-automl
git rev-parse HEAD
git switch -c feat/v3-task-contract
```

Последнюю строку два Plus заменяют своей веткой из распределения. Не работать втроём в main, не делать force push. В приватном репозитории нужен доступ аккаунта; клонирование по HTTPS/SSH настраивается каждым отдельно. API-ключ передаётся лично безопасным способом и задаётся окружением, не через Git или промпты. Публичные CSV каждый получает из пакета организаторов.

## Порядок работы

- **Первые 1–2 часа:** каждый читает `program.md`, разбор вебинара и `v3_contract.md`; подтверждает контракт 0.1. Pro отдаёт минимальную реализацию/описание JSON, Plus A/B начинают независимые unit-тесты по уже записанному контракту, а не ждут полного агента.
- **Первая контрольная точка:** Pro показывает loader+metrics+split тесты; A — model adapter tests; B — planner/budget tests. Все передают SHA и несовместимости. Не подменять факт запуска обещанием ИИ.
- **Интеграция:** капитан или уполномоченный Plus B в отдельной integration-ветке последовательно объединяет Pro → A → B. Самостоятельный merge в main не разрешён этим документом. Ошибки на границах возвращаются владельцу, а не исправляются двумя агентами одновременно.
- **Release gate:** старые тесты + новые contract/adapter/runner тесты, synthetic end-to-end, затем обе public-задачи на одинаковых зафиксированных split и budget. Измерить качество, время, peak RAM и стоимость Qwen. Для новой методики split отдельно объяснить, почему сравнение локальных чисел с прежним split некорректно.
- **После gate:** собрать новый ZIP, распаковать и запустить без состояния разработчика. Приёмка капитаном; отдельное явное согласие на платформенную попытку. Отправленную v2 сохранять независимо от исхода v3.
