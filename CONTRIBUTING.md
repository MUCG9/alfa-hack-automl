# Как работать вместе

Точка входа для нового агента — `AGENTS.md`, `docs/CONTINUE_HERE.md`, `docs/architecture/implementation.md`. Исторические `parallel_work.md`, `v3_contract.md`, Pro/Plus prompts и `program.md` не являются текущим назначением владельцев и не должны отменять новые границы модулей. Рабочая интеграционная ветка — `experiment/modular-augmentation`; main сохраняет v2.

1. Выберите одну задачу из `docs/backlog.md` и согласуйте владельца.
2. Создайте отдельную ветку и меняйте один проверяемый фактор.
3. Передайте ИИ общий контекст, свой issue и актуальный контракт модуля. Не вставляйте API-ключ в prompt.
4. Сохраните фактический запуск, split hash, метрику, время и ограничения проверки.
5. Откройте pull request, получите независимый review. Капитан отдельно утверждает release и расход submit-слота.

Ключи задавайте через окружение. Исходные train/test, локальную среду и большие generated artifacts не коммитьте. Не меняйте исходный `requirements.txt`, evaluator или split ради красивого результата. Следующий ZIP собирайте упаковщиком и проверяйте после распаковки.

Предсказания публичных прогонов исключены из Git. V1/V2/V3 в `release/` — неизменяемые отправленные архивы. Canonical source находится в `src/automl`, root legacy files — shims. Каждый разработчик создаёт отдельную ветку от experimental integration HEAD, а PR направляет в experimental branch, не в main. Локальная метрика не является официальным баллом. Следующий официальный submit требует нового разрешения, даже после reset quota.
