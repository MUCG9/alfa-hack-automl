Новая серия экспериментов по предложенной архитектуре

Проверено по фактическому коду: разрешённых библиотек больше, чем подключённых методов. В runtime есть LightGBM, CatBoost, XGBoost, ExtraTrees и linear_text, который также работает с обычными числовыми/категориальными данными. В текущем T7 на обеих задачах фактически участвовали только ансамбль и три семейства бустингов. Ridge/LogisticRegression/SGD уже реализованы внутри linear_text; отдельные имена tabular engines и обязательное включение в портфель отсутствуют. PyTorch, LightAutoML, AutoGluon и FLAML разрешены requirements, но их metadata отсутствует в текущем локальном окружении; импорт/работоспособность не проверялись.

Добавлены в очередь:
1. ExtraTrees: проверить самостоятельное качество и сохранить прогнозы для оценки разнообразия. Один заранее заданный небольшой лес, те же срезы и сильные контроли, лимит серии6600с.
2. Ridge для регрессии / LogisticRegression для классификации: проверить существующий fitting-only путь numeric/OHE без текста, затем включить его в компонентный screen. Новый адаптер с нуля не требуется. Общий лимит10800с, отдельные ограничения размерности/памяти/итераций.
3. Фиксированный blend90%сильного контроля+10%нового семейства: проверить, полезна ли модель с другим характером ошибок. Без подбора весов по validation; до720с без новых fits по проверенным сохранённым predictions.
4. Навыки выбора метода для Qwen: подготовлен opt-in код --method-skills. Он добавляет инструкции только о реально реализованных инструментах, выбирая их по типу задачи/текстовым признакам. Портфель и метрика остаются теми же. Код прошёл статическую проверку default-OFF AST;6тестов подготовлены, но не запускались. Сначала matched generation screen600с, затем при необходимости полный A/B.
5. Портфель по свойствам fitting-данных и бюджету: сравнить постоянный расширенный список с заранее объявленным правилом допуска методов. Сначала нужны измеренные стоимость и работоспособность новых инструментов.
6. LightAutoML/FLAML/небольшая CPU-сеть: низкоприоритетная проверка реализуемости и накладных расходов, затем отдельный опыт. Эти методы пока не подключены и не предлагаются Qwen как готовые.

Feature engineering, кодирование, sampling и веса остаются отдельными факторами. Увеличение количества методов или наличие скилла само по себе не считается выигрышем. Проверяем итоговую метрику, каждый срез, редкие классы, затраты и реальный refit/CSV. Лучший T5 regression и сильный V11/V16 сохранены.

Очередь и бюджеты: work/method-expansion-program/queue.json. Новые ML-запуски ещё не начаты. T7 завершён с exit0: RMSE34.92368930, MacroF1=0.65692423; технический аудит успешен, quality promotion нет. После этой подготовки возвращаемся к автоматической цели через следующую отдельную техническую проверку champion-архива.
