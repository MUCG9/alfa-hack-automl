# Owner-side closed API usage export: isolated prototype

Future metadata-only prototype. Canonical runtime, active tm1 and inaccessible historical ledgers are untouched. No ACL operations, privilege changes, current-ledger reads, model fitting or API calls occur. The prototype has one runtime-file delta: src/automl/infrastructure/run_budget.py. Deadline, authorization and legacy snapshot behavior are unchanged in a deterministic parity fixture. No new dependencies are used.

At legitimate future RunBudget creation the owner reserves an ordinary persistent automl_runs/api-usage/0001.json artifact, separate from the private creator temporary trace directory. Exclusive ordinal files avoid overwriting earlier contexts. Destination-parent temporary files are also exclusively created and written as exact UTF8 bytes before replace. No temporary-directory rename or permissions modification is used.

The owner writes a sanitized running export on creation/authorization/record and a closed export only during its actual context exit after flushing the original source ledger. That source ledger is read only by its own creating budget instance and hashed from exact persisted bytes. The exported source hash does not prove independent access to the original trace or provider-side billing. A future supervisor independently reads the normal artifact after the owner exits. The test uses one tiny local reader child with a scrubbed environment; no gateway is imported.

The whitelist contains fixed schema/status/purpose strings, counts, finite elapsed time, token usage, completeness flags and source SHA256. It excludes raw errors, exception messages, prompts, response bodies, headers, environment values, model-supplied text, addresses, nonces and absolute paths. Unknown purposes/statuses become unknown. Missing/invalid token counts remain null; retry/inflight totals stay incomplete, with explicitly labeled known sums. The legacy ledger still has its original behavior; separate sanitized events capture unknown values before legacy zero coercion.

Export errors do not add a new search stop or change authorization. They are sticky metadata qualification failures: a future independent gate must require closed=true, source_ledger_closed=true, export_integrity_ok=true, usage_complete=true, allowed terminal status, finite time/cap bounds and valid aggregate arithmetic. Parent report counters cannot substitute for a missing export. A completed export can honestly describe a failed or interrupted solver; usage completeness does not qualify model success.

Limits: this is saved local accounting, not independent provider billing or a team currency/balance estimate. Parser success is not added here because current transport recording occurs separately; no model-selection logic was changed. Independent external clock/owned-process/metrics checks remain required. Ordinary fixture readability is not a guarantee for every future production path; the future live-gate owner must create and close its own artifact at the actual destination and the supervisor must verify normal readability before ML. No existing denied trace is retrofitted.
