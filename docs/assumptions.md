The new specification describes Python 3.12, up to eight CPUs and 32 GB on the
platform, and 10,800 seconds per task. Current research protocols intentionally use
smaller explicit host limits; a platform ceiling does not enlarge a running lease.
Clean-platform compatibility of the new integration is not yet established.

The case and baseline differ in how they name the entry script; the actual
baseline/root `solution.py` contract is the integration authority until tested.
An import in the example baseline does not automatically authorize or require a
new dependency in our runtime. Optional absent libraries are unavailable.

Use only the existing authorized Qwen provider configuration. A requested reasoning
setting is not proof of an effective backend mode. Token usage is measured where
available; ruble cost and remaining daily budget remain unknown without an actual
tariff/quota receipt. No invented price conversion or additional provider keys.

Official normalization uses hidden organizer baseline constants. Local validation
baselines are not substitutes for these constants, and local results are not
official points. Historical class score drift remains unexplained despite matching
recipe lineage. Reused validation is not blind evaluation.

Linux and Windows native split containers differ in ZIP creator and integer dtype;
the ordered canonical rows have independently matched. Native-v3-r2 checks both
platform-specific bytes/headers and canonical values. Solver arrays are not cast,
sorted or rewritten to make a gate pass.

Latest human instructions disable automatic submissions. Earlier separate checked
research/dispatch Git publication authorization persists. Browser-origin access
denial remains binding independently of this policy.
